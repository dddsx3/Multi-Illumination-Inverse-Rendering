## 1. 候选条款

> **D14 候选 · 判据充分性纪律**
> 早停 / 健康 / 收敛等**双值性判据**（触发/不触发、通过/失败、合格/不合格）必须 ≥3 run 复跑；
> 单 run 结论仅作初判；多 run 结论才可作裁决依据。

---

## 2. 反例与证据

### 2.1 INC-0011 反例（F-resA 早停判据反转）
- G-M8 阶段 1 run 跑出"never triggers"结论（INC-0010 v1/v2 采纳）
- Q1 复跑扩展到 4 run → verdict=MIXED（3/4 触发，1/4 不触发）
- v3 处置：MIXED + 软约束 + A3-bis 3-seed 验证

### 2.2 教训
- 早停判据依赖"连续 10 个 batch 达标"统计量，小样本下 std 偏大
- 单值性指标（PSNR）勉强可接受 1 run 验证；双值性结论**完全不充分**
- G-M7 已知跨 run std=12.3%（软约束预算），未在 G-M8 阶段同步收紧

---

## 3. 配套修改

### 3.1 审计规程 §5 抽检规则扩展（v2.2 候选）
- **判据类门禁**（G2.5 / G2.6 / G2.7）的抽检应优先核对"≥3 run"而非单 run 数字
- 单 run 调用必须显式标记"初判"二字

### 3.2 复跑命令模板
- 所有 G-M* 脚本必须接受 `--num_runs N` 参数（默认 3）
- 单 run 调用必须显式 `--num_runs 1` 警示

### 3.3 报告数字可追溯
- 任何"判据"类数字（不仅"指标"）必须可追溯到 ≥3 run 原始数据
- 审计者按 §5 抽检规则扩展核对

## 5. 待评估影响

### 5.1 时间成本
- 任何判据类实验 ×3 run = 3x 训练时间
- 早停判据 100 epoch × 3 run ≈ 16h（替代单 run 5.5h）

### 5.2 工程成本
- 现有 G-M* 脚本需加 `--num_runs` 参数
- INC 记录模板需加"双值性判据 vs 单值性指标"分类

### 5.3 豁免场景
- 冒烟测试（仅用于初判，不入对比矩阵）
- 历史数据复算（仅作存档参考）

---

## 6. 决策建议

**建议纳入 v2.2 顶层设计**（理由）：
1. INC-0011 是真实反例，F-resA 单 run 反转差点导致 v1/v2 INC-0010 走偏
2. 0 行代码成本（仅纪律条目扩展）
3. 与 D10 单变量原则一致，互补而非冲突

**风险**：
- 时间成本 3x 增长——但 5.5h × 3 = 16.5h 在 Phase 2 30h+ 预算内可接受
- 旧实验（如 G-M7 / G-M8）需要重新跑 ≥3 run（额外 30-40h）

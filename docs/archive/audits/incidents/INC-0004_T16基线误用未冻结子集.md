# INC-0004 · T1.6 基线误评在未冻结的场景子集上

- **日期**：2026-08-25（T2.6a 一致性锚点校验时发现）
- **触发**：任务书 G2.6 强一致性锚点校验 FAIL（max_deviation=6.52，normal_median_deg）

## 1. 现象

phase1_best_recovered.pth（epoch95 权重）在冻结 test（127 场景）上的 13 项指标
与 T1.6 报告数字系统性不一致（如 normal_mae_deg 10.21 vs 9.55）；但与更早一次
评估（commit 6399fa9 版本 eval_summary.json）逐位一致。

## 2. 排查与根因

取证对比两次评估的场景名单：
- T1.6 基线 CSV：**121 个场景**
- 冻结 test：**127 个场景**；交集仅 **17**
- 121 = v1 数据集（D:/data/synthetic，601 场景）按 80/20(seed42) 的验证子集数

**根因**：T1.6 基线评估命令的 --data_root 实际指向了 v1 数据集（或其等价状态），
导致"基线"测量发生在未冻结、非本阶段标准的场景子集上。评估脚本不回显 data_root，
使该错误在当时不可见（过程性根因：缺乏输入回显与场景名单存档比对）。

## 3. 影响评估

- T1.6 报告数字本身计算无误，但测量的场景总体与声明不符 => **撤回其"test 基线"
  地位**，改称"偶然的跨版本泛化测量"（数值仍有参考价值：v2 模型在 v1 场景上
  PSNR 36.58 / 法线 9.55，为跨分布迁移提供了意外数据点）；
- 对外传达过的"法线 MAE 9.55°"需更正为官方 test 基线 **10.21°**；
- 对训练无影响（训练用的是正确的 train 划分）。

## 4. 修复

1. evaluate_model.py 在 summary 中回显 data_root 与场景数（防再犯）；
2. 正式 test 基线以本 INC 关联的 T2.6a 运行为准（见 docs/Phase2_T26_test基线.md）；
3. 启动前检查清单新增：评估类命令执行前核对 --data_root 与清单/日志回显一致。

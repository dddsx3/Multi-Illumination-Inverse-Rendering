## 一、核实结论速览

你拿到的升级计划对现状的判断**全部属实**——代码里就是纯 U-Net（Conv+BN+ReLU+MaxPool，无任何注意力机制）、固定 5 张 256×256 灰度图堆叠输入 `[B,5,H,W]`、单视角、多输出头（depth/albedo/SH/weight）、三阶段课程学习、可微分物理渲染器 + 分层残差。这些不再需要论证。

但计划漏掉了**四个比"加 Transformer"更致命的问题**，它们直接决定论文能否成立：

1. **局部残差是一个全局共享的作弊参数**（`residual_modules.py:197-202`）——一张与输入无关的、全数据集共享的可学习缓冲图，相当于给每个 batch 都开了一个"吸收误差的后门"。审稿人看到必毙，而且它严重损害跨场景泛化。计划里完全没有提它。
2. **系统是纯自监督的，没有任何真值**——训练损失只有"重建输入图像"，没有 depth/albedo/normal 的 GT 监督（`loss_functions.py` 全程只拿输入图做目标）。这意味着：(a) 目前无法做任何量化评估；(b) 分解本质上是欠定的（任何 albedo×shading 分解都满足重建损失）。计划把 B1（合成 GT 数据集）当作"实验补齐项"，**实际上它是整个升级的主线**——没有它，方法升不上去，实验也做不了。
3. **"反照率一致性损失"是一个空操作**（`loss_functions.py:416-418`）——当模型只输出单通道反照率时直接返回 0。也就是说计划里 A3 的核心物理先验（跨光照反照率一致性）在代码里**已经有一半骨架，但从未生效**。这既是坏消息也是好消息：这部分是真需求，且改造量不大。
4. **"物理锁定"是手工启发式，不是可发表的物理建模**（`unet_model.py:316-328`）——用 `clamp(SH[0], 0, 1)` 硬限制直流分量，注释里写着"光环粉碎者"（中文注释，英文读者看不懂，审稿人更看不懂）。这正是 A3 要替代的东西，但计划没有把它和现有 hack 的来龙去脉接上——论文里这段历史必须重写为有动机的物理约束（见第五节）。

另有三个复现性/工程问题：仓库里没有评估指标代码、没有 SOTA 对比、没有 `requirements.txt`；`examples/sh_coeffs.json` 里的 SH[0] 值（1.15、1.02、1.81）超过了当前代码 clamp 上限 1.0，说明示例是旧版本代码生成的，与 HEAD 不一致；训练器强制 CUDA（`trainer.py:78-80`），本机无法跑通任何训练脚本做冒烟测试。

## 二、计划判断 vs 代码逐条核实

### 2.1 计划中判断准确的条目

| 计划判断 | 代码证据 | 核实结果 |
|---|---|---|
| 纯 U-Net + 残差 | `unet_model.py:15-134` DownBlock/UpBlock 全为 Conv+BN+ReLU；无 attention/SE/transformer | ✅ 属实 |
| 固定 5 张灰度图 | `config.py:24` `num_lights=5`；输入 `[B, K, H, W]` 直接堆叠；SH 头输出 `[B, K, 9]` 与 K 绑定 | ✅ 属实 |
| 单视角 | 所有光照图同一视角（README 数据格式），无多视角几何信息 | ✅ 属实 |
| 三阶段课程学习 | `trainer.py` 三阶段 + `loss_functions.py:569-627` 阶段权重表 | ✅ 属实 |
| 物理渲染器已具备 | `physics_renderer.py`：Sobel 法线 + 二阶 SH 光照（常数 `C0=0.282095` 等正确）+ albedo×shading | ✅ 属实，且可作为 A3 的现成底座 |
| 可视化 Demo 级验证 | 仓库无任何指标计算、无标准数据集、无对比基线 | ✅ 属实 |

### 2.2 计划遗漏、但更关键的问题（按严重程度排序）

**L1（致命）：局部残差是全局共享缓冲参数。** `residual_modules.py:197-202` 创建一个 `[1,1,H,W]` 的可学习 `nn.Parameter`，不依赖任何输入，**所有场景、所有光照共用同一张**。它的作用是吸收模型系统性误差——训练时网络学会把解释不了的残差都倒进这张图里。后果：跨场景泛化差（这张图是在训练集上过拟合出来的）、测试时仍在生效、论文里无法解释它。这是"分层残差建模"里最弱的一环，**计划中的 A1-A5 任何一项都无法掩盖它，必须先重构**。

**L2（致命）：纯自监督 → 无法量化、分解欠定。** 全仓库搜索不到任何 GT 深度/反照率/法线参与训练。这意味着：(a) 计划 B1 不只是"补数据集"，而是把训练范式从"自监督重建"切换成"带 GT 的物理引导学习"，整个损失体系都要重写（新增 depth/albedo/normal 监督项，重建损失降为辅助项）；(b) 目前方法上的所有正则（平滑、SH 先验、锁定）都是在补偿欠定性，有了 GT 之后这些可以大幅简化，方法叙事反而更干净。

**L3（高）：albedo_consistency 从未生效。** `loss_functions.py:416-418` 单通道反照率时直接 `return 0`。计划的 A3 说"加入法线-深度一致性损失（integrability constraint）"，但仓库里现成挂着一个从未工作的反照率一致性损失——升级时应先把它修活（多光照下反照率应严格一致，这是本任务最自然的物理先验），而不是从零造新损失。

**L4（高）：物理锁定是手工 hack。** `unet_model.py:320-328` 的 `clamp` 出自训练踩坑记录（操作手册第 10 节"Physics Lockdown Mechanism"）。这类工程 hack 直接写进论文会被审稿人视为调参痕迹。A3 的正确做法：把 SH[0] 的约束从硬 clamp 改为**物理推导的软约束**（如光照能量非负 + 辐射度守恒），并把"SH 系数作为网络中间变量、渲染路径作为监督"写成核心方法。

**L5（中）：示例输出与代码不一致。** `examples/sh_coeffs.json` 的 SH[0] 超过 1.0（当前代码 clamp 到 1.0），示例 PNG 无法从 HEAD 复现。投稿前所有可视化必须由最终代码重新生成，否则是复现性硬伤。

**L6（中）：工程配套缺失。** 无 `requirements.txt`、无评估模块、无基线脚本、无 CI。对一区投稿来说，评审要求"可复现"，这些都要补。

## 三、计划中需要修正的判断

**B1 从"实验补齐项"升级为"项目主线"。** 计划把它列为 6-8 周的并行工作，但它其实是 L2 的解药：ShapeNet+BlenderProc 渲染出带 GT（depth/albedo/normal/光照参数）的多光照数据后，(1) 训练可以切换为监督+物理混合范式；(2) 所有消融和对比有了量化基础；(3) 跨数据集泛化（B4）才说得清。建议 Phase 1 只做这件事，架构升级（A1）放在 Phase 2——先有量尺，再谈度量。

**B2"复现/跑通 6 个 SOTA"改为"已发表数字为主 + 重训 1-2 个"。** PS-FCN、SDPS-Net、LCNet 是光度立体的方法，各有各的训练集和协议；逐个大成本复现足以吃掉 3 个月。文献惯例是：在标准协议（如 DiLiGenT 固定训练/测试划分）下直接引用已发表指标，只针对"协议与你不完全一致"的 1-2 个方法（建议 LCNet 或一个 transformer 型方法）用你自己的协议重训。这样对比表 2-3 周可出，且同样有效。

**B5 用公开数据集替代（或补充）手机自拍。** 真实场景定性图在 Supplementary 里有用，但自拍数据缺乏量化锚点。Murmann 等人的 **Multi-Illumination Images in the Wild**（ICCV 2019，1010 个场景、多光源 RGB、带色卡校正）正是"多光照"设定的公开真实数据，比 DiLiGenT（光度立体基准，测法线）和 MIT Intrinsic（仅 20 个物体，太小）更贴题。建议测试集定为：**DiLiGenT（法线，68 个物体，引用已发表 SOTA）+ Multi-Illumination in the Wild（本征分解 + 定性）+ ShapeNet 合成保留集（深度/反照率全量指标）**。MIT Intrinsic 只作补充。

**ECCV/ICCV 是会议，不是 SCI 期刊。** 它们是 CCF-A 顶会（周期短、8-9 页、6 月前完成实验），而"SCI 一区期刊"对应的是 TVCG / TIP / PR / IJCV（实验要求更全、篇幅更长、周期 3-6 个月）。两条路线的验收标准不同，建议明确主目标为**期刊（TVCG 或 PR）**，中途产物可投会议（ACCV/BMCV 级别）做风险对冲——计划第 6 个月的"决策点"方向是对的，但需要现在就定主从关系，避免用期刊的验收标准赶会议的截止日。

**理论包装（A5）可以更硬。** 梯度冲突分析只是"测量"，不是"理论"。真正可写的一区级理论点是：**多光照设定下本征分解歧义性的形式化分析**——单图分解有著名的 albedo/shading 乘积歧义，而多光照（K≥3 且光照线性独立）显著收紧歧义空间，可给出可辨识性（identifiability）讨论 + 网络如何利用光照冗余的机制解释。这一条工作量小（主要是推导和消融佐证），但把故事从"工程技巧"升维成"有定理支撑的方法"。

## 四、修订后的主路线与任务计划

**核心叙事（一句话）**：多光照图像为本征分解提供了光照冗余，本文提出物理引导的 Transformer 逆渲染框架，将这种冗余转化为可辨识的深度/反照率/法线分解——「光照冗余 → 歧义消除 → 物理可解释分解」。

| 阶段 | 时间 | 核心任务 | 产出/验收 |
|---|---|---|---|
| Phase 0 | 第 1-2 周 | 修 L1（重构局部残差为逐场景预测或删除）；修 L3（激活 albedo 一致性）；修 L5（重新生成示例）；补 requirements/评估模块骨架 | 冒烟可跑（你的 GPU 机上）；无作弊参数的干净版本 |
| Phase 1 | 第 3-6 周 | **B1 主线**：BlenderProc 渲染 ShapeNet 多光照数据集（含 GT 深度/反照率/法线/SH 光照）；训练切换为监督+物理混合损失 | ≥200 场景渲染管线跑通；基线上量化指标（normal MAE、depth RMSE、albedo MSE、重建 PSNR） |
| Phase 2 | 第 7-11 周 | A1（Transformer/注意力进 encoder）；A2（任意 N 输入，注意力聚合光照）；A4（RGB 支持，灰度作退化实验）；A3（SH 作中间变量 + integrability 一致性） | 主模型定稿；合成保留集指标显著优于基线 |
| Phase 3 | 第 12-15 周 | B2 对比（已发表数字 + 重训 1-2 个）；B3 消融 ≥10 组（课程阶段、物理损失有无、残差变体、N=3/5/7/9、SH 阶数、注意力有无） | 对比表 + 消融表 |
| Phase 4 | 第 16-19 周 | B4 跨域泛化（ShapeNet→DiLiGenT/Multi-Illumination）；A5 理论：歧义性分析 + 梯度冲突实验 | 泛化结果 + 理论章节素材 |
| Phase 5 | 第 20-23 周 | 真实场景定性（Multi-Illumination 数据集 + 手机自拍进 Supplementary）；A6a（非定标光照）或 A6b（多视角，DiLiGenT-MV）二选一 | Supplementary 完整 |
| Phase 6 | 第 24-27 周 | 论文初稿（期刊版式：TVCG/PR 双栏长文） | 完整初稿 |
| Phase 7 | 第 28-31 周 | 内部审阅 → 图表重绘 → 投稿；同时把中途成熟产物整理成会议版（ACCV 级） | 一区投稿 + 会议保底 |

合计约 8 个月（比原 12 个月压缩，因为 B1 提前、B2 策略修正、Phase 0 修复先行）。总周期弹性 2-3 个月。

## 五、立即可以启动的工作（按机器分工）

**本机（这台云主机，无 GPU——负责代码与数据工程）**，随时可以开始：

1. **L1 重构**：把 `HierarchicalResidual.local_residual` 从全局 `Parameter` 改为由解码器特征逐场景预测的局部残差图（加 L1+TV 正则保持稀疏），或直接删除、仅保留全局残差 MLP 并为其增加空间上下文（改造成小型 U-Net 分支）。
2. **L3 修复**：让反照率一致性损失真正生效（多光照下 albedo 一致是核心物理先验，A3 的一半已经在这里）。
3. **评估模块**：新建 `evaluate.py`（normal 角度误差/MAE、depth RMSE、albedo 误差、重建 PSNR/SSIM），为 B1 的数据集输出格式定协议。
4. **合成数据生成器（CPU 版）**：先用现成的 `PhysicsRenderer` 做程序化合成数据（随机深度场 + 随机反照率 + 随机 SH 光照 → 渲染），让 Phase 1 的"带 GT 的监督训练管线"在 1 周内先跑通小规模验证，再上 BlenderProc。
5. **A1 原型**：在 encoder 中插入轻量注意力（如 Swin-T block 或 CBAM），本机可做参数/速度预研。
6. **BlenderProc 渲染脚本**：写好脚本与配置（ShapeNet 子集选择、光照随机化、GT 导出），交给你的 GPU 机执行。

**你的 GPU 机（代码中 `config.py:19` 指向的 Windows 机器）**：BlenderProc 大数据集渲染、全部模型训练（本机无 GPU 且仅 8GB 内存，训练必须在你那里）、SOTA 方法重训。

**需要你先定的一件事**：A6a（非定标光照，加网络分支，贴近真实、加分但拖期）与 A6b（多视角一致性，数据现成、改动小）目前建议选 **A6b**——它和"光照冗余"叙事天然互补，且 DiLiGenT-MV 数据现成。若 Phase 4 泛化结果理想、时间充裕，再考虑 A6a 作为期刊版增补。

## 六、风险与备选

1. **时间风险**：最大不确定性在 BlenderProc 渲染（CPU 渲染慢，需要 GPU 机的渲染配置验证）和 A1 改造（注意力替换不能破坏现有物理渲染监督路径）。对策：Phase 1 的 CPU 程序化合成数据提前验证训练管线；A1 采用渐进替换（先加在 bottleneck 一个位置，消融里做"位置消融"反而多一个实验点）。
2. **创新性风险**：若 Transformer+物理先验仍被审稿人视为增量，补充方向按优先级：歧义性理论分析（成本低）> 动态场景/稀疏视角新设定（成本高）。
3. **投稿策略**：主目标 TVCG 或 PR；若 Phase 6 前对比+消融+泛化齐全，先投一次 CCF-A 会议（ICCV/CVPR 周期）的期刊版精简稿，被拒则期刊版已有完整实验底座，直接转投，不留空窗。
4. **学术诚信**：B2 引用已发表指标必须标注协议差异；所有示例图用最终代码重新生成（L5）。

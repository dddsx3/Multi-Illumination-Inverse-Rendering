## 3. 根因分层

### 3.1 运行环境与内存配置（本机硬事实）
- GPU：RTX 5070 Ti Laptop，**12GB** VRAM（torch 报 11.94GB）；驱动 591.86；torch 2.12.0.dev+cu128
- 物理内存：**仅 16GB**（/proc/meminfo MemTotal 15.9GB）；**开机即仅剩 4.4–6GB 空闲**（系统+常驻应用占用 ~10–11.5GB）
- 页面文件：C:/D: 各 ~24GB（合计 ~48GB）→ commit 上限 ≈ 64GB
- 温度：**空闲即 73–75°C**（低散热笔记本平台）；热墙 RESUME=75/LIMIT=80（_env.sh 固化）
- 磁盘：数据 D:/data/synthetic_v3 ~1GB+；ckpt 每 epoch 157MB 落盘

### 3.2 训练批次 × 模型规模（bs8 为何不可行）
- FusionUNet 13.7M 参数 + physics_renderer（5 光逐光梯度/渲染）+ 256² 输入 + 全量损失项
- bs8 前向峰值即逼近/越过 12GB；backward 再叠加激活图 + **cuDNN workspace 原始 cudaMalloc**
  （不受 torch 缓存分配器控制）→ 分配失败；bs4 单 epoch 完整可跑 → 每 batch 显存开销近线性，12GB 上限落在 bs∈(4,8]
- `expandable_segments` 只缓解 torch 内部分配碎片，救不了 cuDNN 原始分配与整体峰值

### 3.3 内存持续增长/资源耗尽环节（按风险排序）
1. **多进程残留（已证实）**：崩溃的 spawn worker 不随父进程退出，7 次尝试累积 ~4GB+ 常驻；
   每次新跑又重载 torch/cuDNN（每进程 commit >1GB）→ commit 逐次叠加
2. **commit 内存上限（WinError 1455）**：DataLoader shared-file mapping + spawn 复制 DLL 映射，
   在物理空闲低时先于 CUDA 触发
3. **CUDA OOM 连锁**：VRAM 不足 → cuDNN/cuBLAS 失败 → 部分路径打印 `fatal: Memory allocation failure`
   → 异步 unknown error 在无关算子处浮现（误导定位）
4. **低物理内存 + 页面文件抖动**：16GB 物理被系统/应用占 ~10GB 后，训练+多进程直接吃页面文件；
   页面文件在系统盘 I/O → UI 冻结 → 冷重启
5. 温度墙（LIMIT=80）是 GPU 温控，不保护主机内存；本机空闲 75°C 意味着热墙频繁触发，
   单 epoch 被多次 rc42 打断重进，加重 commit 压力（每个新段重载 DLL）

### 3.4 触发系统停摆的临界点（复盘判断）
训练进程自身 RAM 用量并不大（模型 ~55MB×优化器状态、激活在显存），**停摆主因不是单进程
内存泄漏，而是"低物理内存环境 + 反复崩溃重试的进程残留 + commit 逼近上限 + 页面文件抖动"**
四者叠加：最后一次 bs4+nw0 运行时，物理空闲进入 1–3GB 区间后系统进入 thrash，UI 无响应，
普通重启流程无法完成 → 冷重启。

## 4. 修复（本次落地）

1. **新增 `runtime_safety.py`**：运行前闸门——物理内存/页面文件/GPU 温度/VRAM 可行性表
   （bs8 实测不可行硬 BLOCK）/残留 python 单实例互斥/磁盘；运行中 `check_host_memory()`
   每 10 batch 熔断（物理 <1.5GB 或页面文件 <2GB → MemoryStop）
2. **trainer.py / main.py**：内存熔断复用温度墙通道——`interrupt_state.pth` 存档 → rc=42 →
   编排器恢复（loss ≤ 若干 batch，永不硬杀）
3. **`monitor_host.py`**：独立观测哨兵，3s 采样写心跳日志，持续低于硬地板打 CRITICAL/ALERT
4. **`run_safe_arms.sh`（强制入口）**：自检 → bs8 自动降配 bs4（提示）→ bs4 仍 BLOCK 则终止 →
   带哨兵启动 run_arms；**后续一切训练禁止裸跑**
5. **run_arms.py**：`BATCH_SIZE` 支持 `RUN_ARMS_BATCH` 环境变量（默认仍 8，本机走降配路径）
6. 附带清理：删除全部残留 python 进程；后续 git 大提交与文档（run_arms A3-0 臂、骨架文件、
   误命名文件改名）统一提交

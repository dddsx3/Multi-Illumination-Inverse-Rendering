# 事故记录索引（Incidents）

本目录持久化项目执行过程中的生产事故与根因分析。每起事故独立编号，
格式 `INC-XXXX_简短标题.md`。新事故发生时按模板新建文档并在下方索引登记。

使用原则：
1. 任何导致返工/数据损失/资源浪费 ≥30 分钟的异常都应立档；
2. 修复措施必须落到代码或脚本（守卫/断言/分块），只写文档不写代码视为未修复；
3. 长任务启动前过一遍文末「启动前检查清单」。

## 启动前检查清单（长时训练/渲染任务通用）

- [ ] 冒烟是否覆盖了所有阶段/模式切换点？（本次教训：3 epoch 冒烟没跑到权重表切换）
- [ ] 预裁剪梯度范数首几个 epoch 是否在健康量级（<10^2）？>10^3 即预警
- [ ] AMP 是否开启？开启则必须有 NaN 守卫 + 对照关闭的重跑预案
- [ ] 历史遗留的极端超参（如 albedo_smooth=50）在新数据域下是否重新校准？
- [ ] 渲染/外部引擎长跑是否分块（<=50 单位/进程）并有逐块日志？
- [ ] 失败场景是否自动清理半成品目录且可幂等续跑？
- [ ] 关键产物（best checkpoint / validation.json）是否有独立的存档路径？

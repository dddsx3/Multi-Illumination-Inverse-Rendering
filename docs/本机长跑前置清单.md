# 本机长跑前置清单（Windows / RTX 5070 Ti Laptop）

**用途**：本机跑训练前逐项过一遍。清单来自 INC-0001/0002/0005/0006/0007
以及两次热保护关机、两次 WinError 1455 的实测教训。

---

## 1. 两个已知的本机硬约束

### 1.1 提交内存不足 → WinError 1455「页面文件太小」

实测配置：物理内存 **15.2 GB**，页面文件 C: 系统托管 + D: 固定 24 GB，
提交上限合计 **32.4 GB**。

问题在于 PyTorch CUDA 后端会为一堆 `.dll`（cufft/cublas/cudnn 等）保留巨量
提交内存，与 GPU 显存无关。当**同时**有多个 python 进程持有 CUDA 上下文时，
32.4 GB 的提交上限会被吃满，后启动的进程在 `import torch` 阶段就抛
`OSError: [WinError 1455]`——它发生在加载 DLL 时，跟 batch_size 无关，
调小 batch 无用。

已发生两次：`_probe_a/_probe_b`（审计报告 Q5）、以及 V100 管线本地复验。

**规避**：

- 本机**同时只跑一个** CUDA 进程。开跑前确认没有残留：
  ```bash
  powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='python.exe'\" | Where-Object { \$_.CommandLine -match 'main\.py|run_arms|evaluate_model' } | Select-Object ProcessId"
  ```
- 训练与评估**串行**，不要并行（`run_arms.py` 默认单车道，本机不要加 `--max-lanes`）；
- 如需并行或跑更大配置，先把 D: 页面文件上调到 48000 MB（需重启生效）。

### 1.2 散热能力退化 → 热保护关机

实测：**空闲温度 73–74 °C**（零负载、8 W）。GPU 功耗墙被拉到 **123.57 W**
（默认 65 W），持续负载 2–3 分钟即冲到 85 °C+，已导致两次整机关机。

**规避**（按有效性排序）：

1. 物理层：清灰、确认风扇转动、加散热垫、降低室温——空闲 74 °C 说明散热系统
   已严重退化，软件手段只能缓解；
2. 管理员终端执行一次 `nvidia-smi -pl 65`（把功耗墙压回默认；重启失效需重设）。
   非管理员会报 `Insufficient Permissions`；
3. 软件节流：`THERMAL_PACE=1.0`（秒/批次）。每个 batch 后微暂停以压低平均功耗，
   **只影响墙钟，不改变任何训练数学**（不碰超参、不碰随机流，D10 口径不变）；
4. 看门狗：`thermal_supervisor.ps1` —— 30 s 巡检，≥80 °C 杀训练、≤75 °C 自动续跑。
   编排器幂等，杀了不丢进度。适合无人值守，但代价是"跑几分钟停一次"的喘息循环，
   吞吐很低。

## 2. 开跑前逐项确认

- [ ] 无残留 CUDA 进程（见 §1.1 命令）
- [ ] GPU 温度 ≤ 75 °C：`nvidia-smi --query-gpu=temperature.gpu --format=csv,noheader`
- [ ] 磁盘可用 ≥ 16 GB/臂（每 epoch 一个 157 MB checkpoint，D5 全存档）
- [ ] 目标 run 目录不存在或确认可续跑；**不要**写入单一生产路径（INC-0003）
- [ ] 待续跑的 run 目录内无 `_CONTAMINATED_*.md` 标记（INC-0006，作废 run 不得续跑）
- [ ] 精度与既有基线一致（本机支持 bf16，保持 bf16 即可，不要无谓换 fp16）

## 3. 推荐启动方式

```bash
cd repo
# 前台（可盯着看）
THERMAL_PACE=1.0 python -u run_arms.py --data_root D:/data/synthetic_v3 --budget-hours 24

# 无人值守（带温度看门狗，吞吐低但安全）
powershell -NoProfile -ExecutionPolicy Bypass -File thermal_supervisor.ps1
```

进度：`python run_arms.py --status`；日志：`_arms_main_log.txt`、`_arm_<run_id>_log.txt`。

## 4. 出事之后

| 现象 | 处置 |
|---|---|
| WinError 1455 | 杀掉多余 python 进程，串行重跑；仍失败则上调页面文件 |
| 热保护关机 | 等温度 ≤75 °C 再启；重跑同一命令自动续上；核对最新 checkpoint 完好 |
| 续跑后 loss 异常抬升 | 检查日志是否有「损失权重表已同步到阶段N」字样；若无，说明跑的是旧代码 |
| 训练自动停机 | 读停机原因：非有限损失连击 / 梯度范数 >1e4 / fp16 scale 无法收敛，按 D1 记 INC |

任何失败/重跑/修复都要按纪律 D1 记 `docs/incidents/INC-XXXX_名称.md`。

# Inverse Rendering Project — Operations Manual

## 1. Overview

This project implements a deep learning-based inverse rendering system that decomposes multi-illumination images into depth maps, albedo maps, and lighting parameters. The system uses a U-Net architecture for intrinsic image decomposition and a physics-based renderer to reconstruct images, providing supervision for model learning.

### Core Capabilities
- Decompose depth, albedo, and spherical harmonic lighting coefficients from multi-illumination images
- Edge-aware rendering with directional lighting model
- Hierarchical residual modules for non-Lambertian reflectance
- Three-stage curriculum learning: geometry → material → residual
- Full training, testing, and demonstration modes

## 5. Model Architecture

### U-Net Architecture
- **Encoder**: 4 downsampling layers extracting multi-scale features
- **Bottleneck**: Feature fusion
- **Decoder**: 4 upsampling layers restoring spatial resolution
- **Output Heads**:
  - Depth head: predicts depth map [B, 1, H, W]
  - Albedo head: predicts albedo map [B, 1, H, W], sigmoid activation
  - Weight map head: predicts adaptive weight map [B, 1, H, W], sigmoid activation
  - SH head: predicts spherical harmonic coefficients [B, K, 9], tanh activation

### Physics Renderer
- Supports edge-aware rendering, preserving object boundaries
- Supports directional lighting model, simulating realistic illumination
- Input: depth map, albedo map, SH coefficients
- Output: rendered image, normal map, shading map

### Hierarchical Residual Modules
- Handle non-Lambertian reflectance effects
- Contain global and local residuals
- Input: albedo map, shading map, normal map, SH coefficients
- Output: final rendered image, global residual, local residual

## 6. Training Pipeline

### Three-Stage Curriculum Learning
1. **Stage 1**: Geometry Learning
   - Focus on learning depth maps and lighting parameters
   - Enforce flat albedo to prevent texture leakage
   - Constrain lighting mean to prevent numerical explosion
2. **Stage 2**: Material Learning
   - Fine-tune lighting and material parameters
   - Introduce albedo consistency constraints
3. **Stage 3**: Residual Learning
   - Enable residual modules to handle non-Lambertian reflectance
   - Fine-tune all parameters to improve overall quality

### Training Steps

## 9. Loss Functions

### Primary Loss Functions
- **Reconstruction loss**: Measures difference between predicted and ground-truth images
- **Depth smoothness loss**: Maintains smooth depth maps
- **Albedo smoothness loss**: Enforces flat albedo, prevents texture leakage
- **Weight distribution loss**: Constrains weight map distribution
- **Weight total variation loss**: Maintains smooth weight maps
- **SH L2 loss**: Prevents SH coefficient explosion
- **SH higher-order loss**: Encourages use of higher-order SH coefficients
- **SH sparsity loss**: Encourages sparse SH coefficients
- **Albedo consistency loss**: Ensures consistent albedo across different illumination
- **Residual L1 loss**: Constrains residual magnitude
- **Residual total variation loss**: Maintains smooth residuals

### Custom Loss Functions
- **DepthVarianceLoss**: Enforces sufficient depth variance, prevents flat depth
- **ShadingMeanLoss**: Enforces shading mean of 1.0, prevents numerical explosion
- **ShadingVarianceLoss**: Enforces sufficient shading variance, prevents uniform lighting

## 10. Physics Lockdown Mechanism

To prevent the model from explaining away texture by simply scaling ambient light, the project implements a physics lockdown mechanism:

### Implementation Location
- **File**: `unet_model.py`
- **Location**: Physics constraint application in the `forward` method

### Core Code
```python
# Physics lockdown: ambient light must not exceed 1.0
# This disables SH[0]'s "gain amplifier" function
# The model is forced to use higher-order coefficients to explain texture and vignetting
# Uses non-in-place operations to preserve gradient computation
sh0_clamped = torch.clamp(sh_coeffs[:, :, 0:1], 0.0, 1.0)
sh_higher = sh_coeffs[:, :, 1:]
sh_coeffs = torch.cat([sh0_clamped, sh_higher], dim=-1)
```

## 12. Common Issues and Solutions

### 1. Out-of-Memory Error
- **Error**: `CUDA out of memory`
- **Solutions**:
  - Reduce batch size (`batch_size`)
  - Reduce image size (`image_size`)
  - Enable mixed precision training (`use_amp=True`)

### 2. Gradient Computation Error
- **Error**: `one of the variables needed for gradient computation has been modified by an inplace operation`
- **Solutions**:
  - Ensure all operations are non-in-place; avoid `inplace=True`
  - Check the physics lockdown code in `unet_model.py` for non-in-place operations

### 3. Unstable Training
- **Symptoms**: Large loss fluctuations or NaN values
- **Solutions**:
  - Reduce learning rate (`learning_rate`)
  - Increase weight decay (`weight_decay`)
  - Verify data loader; ensure correct data range
  - Enable gradient clipping (`gradient_clip`)

### 4. Albedo Leakage
- **Symptoms**: Albedo map contains excessive texture
- **Solutions**:
  - Increase `albedo_smooth` weight
  - Enable `aggressive_albedo_smooth`
  - Verify Stage 1 configuration; ensure albedo smoothness constraint is strong enough

### 5. Lighting Numerical Explosion
- **Symptoms**: SH coefficients too large, rendered images too bright
- **Solutions**:
  - Increase `sh_l2` and `shading_mean` weights
  - Verify physics lockdown code; ensure SH[0] is properly constrained
  - Reduce learning rate, especially for the SH coefficient head

## 15. Performance Optimization

### Memory Optimization
- **Enable mixed precision**: Set `use_amp=True`
- **Use gradient accumulation**: Simulate large batch training for big batches
- **Reduce intermediate variables**: Optimize forward pass to minimize unnecessary intermediates

### Speed Optimization
- **Use CUDA streams**: Overlap data transfer and computation
- **Enable CUDA graphs**: Accelerate for fixed input sizes
- **Optimize data loading**: Use `num_workers>0` and `persistent_workers=True`

### Model Optimization
- **Model pruning**: Remove unimportant parameters
- **Quantization**: Consider INT8 quantization for faster inference
- **Knowledge distillation**: Use a larger model to guide a smaller model
